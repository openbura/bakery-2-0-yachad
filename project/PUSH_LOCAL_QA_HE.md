## מה מחובר

- הזמנה שנשמרת מכינה התראה לבעלים; אישור ההזמנה מכין התראה ללקוח שנרשם. שני האירועים נוצרים מטריגר על היסטוריית הסטטוס באותה טרנזקציה, אחרי שמירת המוצרים והסכום. rollback אינו משאיר התראה, ו־replay אינו יוצר התראה כפולה.
- תור משלוחים קבוע עם מזהה אירוע, מנוי, ניסיונות, backoff, תפוגה ו־lease. הרשמה מיד אחרי אישור יוצרת השלמה לאירוע הקיים, בלי כפילות. מכשיר בעלים שנוסף מקבל גם בקשות ממתינות שלא נצפו מעשר הדקות האחרונות.
- worker עצמאי ממסכי הלקוח והבעלים. סגירת הדף אינה עוצרת את תור השליחה. מקומית הוא רץ בשרת הבדיקה; הוכנו Edge Function וקובץ הפעלה ל־pg_net ול־Cron בתשתית Supabase הקיימת.
- רישום Push אופציונלי, בדיקת מצב אמיתי בשרת, הפסקה, חידוש ואיפוס מנוי שהשתנה. סירוב להרשאה אינו חוסם הזמנה. יציאה יזומה מהאדמין מסירה את מנוי המכשיר לפני ההתנתקות; אם גם ביטול השרת וגם ביטול הדפדפן נכשלו, מוצגת אזהרה.
- שני manifests נפרדים ושני רישומי Service Worker על ה־origins הנפרדים. אותו קוד worker משמש בשניהם, עם audience מפורש. אין fetch handler או מטמון offline להזמנות/Auth/checkout.
- ההתראה במסך נעול כוללת הודעה כללית בלבד. לחיצה פותחת מעקב לקוח או `/orders` עם התחברות רגילה. לחיצה או סגירה אינן ״ראיתי״ ואינן אישור הזמנה.

## אייפון ואייפד

נדרשים iOS/iPadOS 16.4 ומעלה, הוספה למסך הבית והרשאה בעקבות לחיצה. אין צורך במנוי Apple Developer. בהתקנה חדשה אין להניח שאחסון Safari או התחברות קיימת מועתקים לאפליקציה. לכן בלקוח: מעתיקים את קישור המעקב, מוסיפים למסך הבית, פותחים את האפליקציה, מדביקים את הקישור במסך `/notifications` ומפעילים עדכונים. הבעלים פותח את האפליקציה המותקנת, מתחבר ומפעיל התראות. אם מופיע ״פתיחה כיישום אינטרנט״, משאירים אותו פעיל.

המימוש משתמש בפרוטוקול Web Push וב־VAPID, עם הספרייה הפתוחה `web-push@3.6.7`. אין ספק SMS, חשבון Firebase, שירות WhatsApp בתשלום או מנוי Apple Developer. הספרייה ו־17 תלויותיה הותקנו **באישור מפורש, בתיקיית בדיקות מבודדת בלבד**: `review/push-tools`. לא הותקנה תלות חדשה באפליקציות הציבורית או באדמין.

ההפעלה העתידית משתמשת במשאבי Supabase הקיימים. אין עמלת הודעה של SMS, אך אין הבטחת תשתית חינמית בכל נפח: צריך לבדוק את מכסות החשבון הקיים לפני הפעלה. ה־Cron שהוכן בודק את התור פעם בדקה וקורא ל־Edge Function רק כשיש משלוח שמגיע זמנו; אין קריאת Edge קבועה כשהתור ריק. [תזמון Supabase](https://supabase.com/docs/guides/functions/schedule-functions), [מכסות Edge](https://supabase.com/docs/guides/platform/manage-your-usage/edge-function-invocations), [הספרייה](https://github.com/web-push-libs/web-push).

## אבטחה ופרטיות

- VAPID private key וסוד ה־worker נשארים בשרת. אין service key, JWT או סיסמה בקוד דפדפן/התראה/קישור/לוג. מפתח הבדיקה המקומי מתמיד בתיקייה מוחרגת מ־Git ואינו מודפס.
- טבלאות המנויים והתורים נמצאות בסכמה פרטית עם RLS ובלי grants לדפדפן. RPC ללקוח דורש את קישור המעקב הנכון; RPC לבעלים דורש מנהל פעיל. כל מכשיר מוגן גם בסוד אקראי מקומי. worker בלבד רשאי לקבל משימות ולסמן תוצאה.
- כתובת ספק Push מאומתת ברישום ושוב בשליחה: HTTPS, רשימת hosts מדויקת, בלי credentials/fragment/פורט אחר, בלי redirects. DNS נבדק ונקשר לכתובת ה־TLS בפועל; כתובות מקומיות/פרטיות נדחות. יש deadline ל־DNS ולבקשת HTTPS.
- payload מוצפן מוגבל ל־`version`, `eventId`, `orderId`, `kind`. אין שם, כתובת, טלפון, פריטים או tracking token. רק במכשיר הלקוח נשמר ב־IndexedDB מיפוי מוגבל לקישור המעקב; הוא מאפשר פתיחה בלחיצה בלי לשמור token גלוי במסד.
- סטטוס ״נשלח״ מציין שהספק קיבל את הבקשה, לא שהלקוח ראה אותה. `tag/topic` קבועים מצמצמים כפילויות; אין הבטחת exactly-once לאחר קריסת שרת בין קבלת הספק לשמירת התוצאה.
- 404/410 משביתים מנוי. 429/5xx/timeout משאירים ניסיון חוזר עם גבולות ונענים ל־Retry-After. שינוי הרשאת מנהל, ״ראיתי״, ביטול הזמנה או תפוגה נבדקים שוב לפני שליחה. ארבעה משלוחים נלקחים בכל גל עם leases טריים.

## מה נבדק ומה עדיין לא

בדיקות מקומיות: 23 בדיקות SQL/worker/הצפנה, שבע בדיקות Service Worker ו־14 תרחישי דפדפן לרישום, אישור, רענון, RTL ורספונסיביות ב־390/430/768/1440/1920. בנוסף נבדקו סירוב להרשאה, שחזור באייפון, הפסקה, logout, כשל רישום, אובדן סוד המכשיר ושלילת הרשאה בזמן שהעמוד ברקע. הבדיקות משתמשות במנוי דפדפן מדומה ובשער שליחה מקומי שחוסם כל פנייה לספק Push.

נבדקו VAPID והצפנה אמיתיים דרך הספרייה, וגם פענוח עם מפתח המכשיר בבדיקה. נבדק שהשרת משגר משימה גם אחרי סגירת דף הבעלים. בדפדפן Chrome אמיתי ה־Service Worker קרא בהצלחה ל־`showNotification` לאחר סגירת דף האפליקציה, עם PushEvent מוזרק. הדפדפן האוטומטי לא מחזיר התראות OS גלויות דרך `getNotifications`; ניסיון לאמת זאת נשמר כגבול הבדיקה, ולא כהוכחת מסירה. אין כאן בדיקת APNs/FCM אמיתית או צילום מסך נעילה פיזי.

הבדיקות הקודמות של ההזמנות נשמרו: 24 SQL ו־17 domain הורצו שוב, וכן בדיקות דפדפן ממוקדות של איסוף, דחייה, תגובה שאבדה, ACK שנכשל וצליל חוזר. שתי האפליקציות נבנו ונבדקו ב־lint; npm audit שלהן ושל כלי ה־Push המקומי דיווח אפס התראות. קיימת באדמין אזהרת bundle מעל 500KB.

בדיקת הקלדה מהירה חשפה גם מרוץ קטן בטופס הקיים: מיקוד ראשוני שהתעכב יכל להחזיר את הסמן לשם בזמן הקלדת הטלפון. נוסף guard שמכבד שדה שכבר קיבל מיקוד, וביטול ה־frame ביציאה מהמסך. ההרצה שנכשלה נשמרה, והתרחיש הורץ שוב אחרי התיקון. תוקנה גם טעינת שתי גרסאות runtime של React באדמין בעקבות הרכיב המשותף, באמצעות dedupe בהגדרת Vite.

**לא אומתו:** Deno/Edge Runtime אמיתי, Postgres 17 מרובה חיבורים, Supabase Auth/Realtime אמיתיים, pg_net/Cron/Vault בענן, קבלת התראה דרך ספק ומכשיר פיזי נעול. אין שרת Deno או Supabase CLI מקומי מותקן; לכן SQL נשמר ב־`supabase/changes`, ולא הומצא שם מיגרציה. קוד הליבה נבדק ב־Node וב־PGlite 18; מתאם ה־Edge וההפעלה בענן נשארים לבדיקה מבודדת לפני שחרור באישור נפרד.
